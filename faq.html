Frequently Asked Questions

How it works, what it isn't, and how to extend it.

How often is data updated?

Institutional holdings are quarterly (up to 45 days stale). Market tape (order flow, relative strength) updates every session at market close. Nowcast bridges the gap with modelled inference. Setup detection runs live as price updates in real time.

Can I trade this system 24/7? Crypto? Futures?

No. The system is built for US equities swing trading on a daily timeframe. Institutions file historical data only on equities; futures and crypto have no historical data disclosure. The Screener, Playbook, and Backtest all assume daily OHLCV bars. Intraday trading invalidates the cone-of-uncertainty math baked into the setup criteria.

Is this automated trading?

No. Every order is placed and exited by hand in your broker. The desk is a decision-support calculator — it scores quality, keeps a journal, and runs simulations. It does not connect to a broker API or place orders.

What if I want to change the position-sizing formula?

Edit the tool directly — it's a single self-contained HTML file in tool/index.html with no build step. The 0.75% risk-per-trade default in the README is the user's starting parameter, not law. Change it to 1% if that fits your account and tolerance.

How does the retry queue work?

Every feed failure (rate limit, 5xx, network) is classified and persisted per (ticker, feed). Rate-limit failures trigger a 30-minute defer of the whole queue — we probe, not replay, so the first failed call waits, then retries; we don't keep hammering. 404 errors (delisted tickers) are marked stalled and never retried.

Can I extend this or integrate it with another platform?

Yes. The backend is zero-dependency Node + SQLite. Data persists in data/swingsys.db. Every API endpoint is documented in server.js. Layers.html and tool/index.html can stay self-contained HTML files or be rebuilt into a frontend framework — they're yours to modify. The decision engines in server/flow/ are pure JS with 90+ tests covering edge cases.

Keep the HTML tools self-contained. The whole point is opening one file and having it work offline. No build step, no npm install for the user, no CDN scripts. If you rebuild, respect that.
