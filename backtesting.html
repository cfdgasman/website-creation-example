05 — Validation · Layer 4

Backtesting

Historical signal performance. Does your setup have an edge, or just a track record?

The Backtest tab replays the Playbook's Setup A/B/C detection over 750 stored daily bars (3+ years) and measures performance — win rate, average R, expectancy, drawdown.

multi-period validation

Performance is measured multi-period: the model is retrained from scratch at each fold, tested only on bars strictly newer than the training set, with a 1-session purge at the boundary. A single 80/20 split on ~50 sessions has a 95% confidence interval 14 points wide — useless. multi-period with 30+ folds is meaningful.

Win rate vs expectancy — the key insight

Setup A has a 22% win rate but +0.47R average — a few large winners carry many small, planned losses. Setup B has a 42% win rate but only +0.12R average — more frequent but smaller. Both are profitable, just different risk profiles.

  • Expectancy = (Win% × Avg Win) − (Loss% × Avg Loss) — net edge per trade risked
  • Positive expectancy is necessary but not sufficient; you still need discipline on position sizing and exit timing
  • Baseline comparison — MA crossover gets −0.35R, showing your Playbook has a real edge

Predictor (experimental) ML model

An optional machine-learning model trained on multi-period folds to predict next-session direction. Measured against the base rate ("always up" — daily closes drift up). Honest verdict when the interval covers the base rate: "no measurable edge."

  • Purged multi-period, never one split — the model is retrained from scratch at each fold
  • Baseline is majority class — "always up" on most tickers beats 50%, so you have to beat that, not randomness
  • Standardisation fitted on training rows only — live prediction uses the fold's own scaling
  • Ensemble spread reported — one random seed is one opinion; two runs of the same net can disagree
Most tickers have no measurable edge. That's the expected result on ~70% of names and is not a bug. A multi-period interval that covers the base rate means the model cannot tell signal from noise on that ticker with that data. Run the Playbook setups instead — they have edge across the board.
